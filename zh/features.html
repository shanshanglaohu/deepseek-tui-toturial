功能指南

深入探索使 DeepSeek TUI 成为强大开发平台的高级功能。

子代理（Sub-Agents）

子代理是 DeepSeek TUI 并行工作的核心。你可以生成多个并发运行的子代理，每个专注于单一任务，然后综合它们的结果。

为什么使用子代理？

  • 速度：并行调查比顺序阅读更快
  • 深度：每个子代理深入专注于一件事
  • 成本：DeepSeek V4 Flash 每百万输入仅 $0.14——子代理很便宜

子代理类型

类型角色使用场景
explore探索调查理解不熟悉的代码、扫描模块树
plan策略规划设计架构、制定实施计划
implementer代码实现编写代码、应用补丁、构建功能
review代码审查代码 Review、安全审计、质量门禁
verifier验证测试运行测试、验证行为

模式：并行调查

概念示意
# 并行生成子代理来调查独立文件
agent_spawn("分析 auth 模块", type="explore")     # 并发运行
agent_spawn("分析 API 路由", type="explore")      # 并发运行
agent_spawn("分析数据库层", type="explore")        # 并发运行

# 等待全部完成后综合结果
agent_wait(wait_mode="all")

并发上限

默认最大并发数：10 个子代理（可通过 [subagents].max_concurrent 配置）。对于更大批量的任务，先达到上限，等待完成后生成下一批。

RLM — 递归语言模型

RLM 用于处理超出上下文窗口的输入——完整文件 >50K tokens、长对话记录、多文档语料库。它将输入加载到 Python REPL 中，你可以通过子 LLM 调用来处理。

RLM 三种模式

  • CHUNK 分块：将大输入拆分，分别处理，综合结果
  • BATCH 批量：并行分类/提取多个独立项目
  • RECURSE 递归：分解 + 批评，用于复杂分析
💡 何时使用 RLM

在输入确实很大时使用 RLM。对于精确计数或结构化聚合，直接在 REPL 中用 Python 计算，报告确定性结果。

任务管理

DeepSeek TUI 提供了持久化任务系统，用于长时间运行、可重启的工作。任务跨会话持久化，并通过结构化证据跟踪进度。

任务原语

  • task_create：将持久化后台任务加入队列
  • task_list / task_read：监控进度和历史
  • task_cancel：取消排队中或运行中的任务
  • task_gate_run：运行验证门禁（fmt、clippy、test）

任务证据

任务记录结构化证据：门禁结果、PR 尝试、验证备注和文件变更。这为复杂的多步骤工作创建了审计追踪。

技能系统

技能是存储在 SKILL.md 文件中的本地指令集。它们用特定领域知识扩展 DeepSeek TUI 的能力——从 Android Clean Architecture 到内容营销。

技能生命周期

  1. 安装：技能存放在 ~/.deepseek/skills/
  2. 发现：可用技能在会话头部列出
  3. 加载：调用 load_skill("skill-name") 将 SKILL.md 内容加载到上下文
🎯 技能创建器

使用内置的 Skill Creator 技能来创建你自己的领域特定技能。它会引导你完成 frontmatter、结构和最佳实践。

创建自己的技能

技能是一个包含 SKILL.md 的目录。创建一个简单的示例：

SKILL.md
---
name: my-python-style
description: 当编写或审查 Python 代码时使用此技能。
---

# Python 代码风格指南

- 使用 type hints 标注所有函数
- 优先使用 dataclass 而非普通类
- 使用 ruff 进行格式化和 lint
- 行宽上限 100 字符

技能命令：/skills（列出）、/skill <name>（激活）、/skill new（创建）、/skill install github:<owner>/<repo>（社区安装）。

MCP 服务器

DeepSeek TUI 支持 Model Context Protocol (MCP)，可以连接外部工具服务器来扩展能力。

配置示例

在 ~/.deepseek/mcp.json 中配置：

mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me"]
    },
    "sqlite": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path", "./data.db"]
    }
  }
}

配置后，MCP 服务器的工具会自动注册为 mcp_<server>_<tool> 格式。使用 deepseek mcp list 查看已配置的服务器，deepseek mcp validate 验证连接。

GitHub 集成

DeepSeek TUI 与 GitHub 集成，用于 Issue 跟踪、PR 审查和结构化验收工作流。

可用操作

  • github_issue_context：读取 Issue 正文和评论
  • github_pr_context：读取 PR 及 diff 和审查状态
  • github_comment：发布有据可查的评论
  • github_close_issue：附验收证据关闭 Issue

所有写操作都需要结构化验收证据——你无法在没有证明工作完成的情况下关闭 Issue。

记忆系统

DeepSeek TUI 支持跨会话持久化记忆。启用后，Agent 会记住你的偏好和重要决策，在后续会话中自动引用。

启用方式

Shell
# 设置环境变量启用记忆
$ export DEEPSEEK_MEMORY=on

# 或在 config.toml 中配置
# [memory]
# enabled = true

记忆文件存储在 ~/.deepseek/memories/，以项目为维度组织。Agent 会在相关任务时自动调用 note 工具记录重要信息。

💰 成本提示

TUI 头部显示实时成本芯片。会话结束时查看总费用。使用缓存感知工作流（追加而非重排）可将缓存命中率保持在 80% 以上，大幅降低成本。

清单与计划

DeepSeek TUI 的规划系统使复杂工作可见且可跟踪。侧边栏显示 Plan / Todos / Tasks / Agents，让你始终了解当前进展。

规划工具

  • update_plan：高层策略（3-6 个阶段）
  • checklist_write：当前阶段下的细粒度叶子任务
  • checklist_update：将任务标记为进行中或已完成

最佳实践

在开始工作之前始终创建 checklist_write。即使有自动批准，可见的跟踪也能展示工作的完整性，并帮助用户跟随你的进度。
