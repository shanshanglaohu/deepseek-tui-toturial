Hands-On: Build a Portfolio Website

Use DeepSeek TUI end-to-end to create a complete single-page portfolio site and deploy it live.

🎯 What You'll Learn
  • How to describe project requirements in natural language so DeepSeek generates complete code
  • How to switch between Agent and Plan modes for different tasks
  • How to review, give feedback, and iterate on AI-generated code
  • How to go from zero to deployed in one session

Step 1: Setup

1.1 Create the project directory

Terminal
$ mkdir ~/my-portfolio
$ cd ~/my-portfolio

1.2 Launch DeepSeek TUI

Start in Agent mode (default — suitable for tasks that modify files):

Terminal
$ deepseek

1.3 Describe your project

This is the most important step. The more specific the prompt, the better the result.

DeepSeek TUI — First prompt
Create a single-page personal portfolio website for me. Requirements:

Project structure:
- index.html (main page)
- css/style.css (styles)
- js/main.js (scripts)

Page content:
1. Navbar: fixed at top, links for "Home, About, Skills, Projects, Contact"
2. Hero section: name ("John Doe" as placeholder), one-line tagline, a CTA button
3. About me: two paragraphs of placeholder intro text
4. Skills: 6 skill cards (HTML, CSS, JavaScript, Python, Git, Linux) with icons
5. Projects: 3 project cards, each with title, description, and tech tags
6. Contact: email and social media links

Design requirements:
- Dark theme (background #0e0e10, light text)
- Responsive layout (looks good on desktop and mobile)
- Use CSS custom properties for colors
- Highlight nav link when scrolling to that section

Please first list the file structure plan and wait for my confirmation before writing code.
💬 Prompt Breakdown

Note the structure: explicit file list + section-by-section description + design constraints + plan-before-execute. The final sentence makes the agent show its plan first — giving you a chance to course-correct before it writes 300 lines of code.

1.4 Confirm the plan

The agent will return a file structure plan and ask for your confirmation. Review it, then reply "looks good" or "confirmed" to start code generation.

Step 2: Generate the Scaffold

The agent will create index.html, css/style.css, and js/main.js in sequence.

2.1 Preview the result

Open it in a browser:

Terminal (WSL)
$ cmd.exe /c start index.html

On macOS: open index.html; Linux: xdg-open index.html.

2.2 If something looks off...

Tell the agent directly what to fix:

DeepSeek TUI
The navbar background is too dark. Make it semi-transparent. Also, the hero text is too large on mobile — please reduce it.

Step 3: Review & Iterate

3.1 Switch to Plan mode for code review

Press Tab to switch to Plan mode (read-only) and have the agent review without modifying:

DeepSeek TUI (Plan mode)
Review css/style.css for responsive design issues. Check for:
1. Missing breakpoints
2. Inconsistent spacing
3. Accessibility issues (insufficient contrast, etc.)

Report issues only — do not modify the file.
🔄 Mode Switching Strategy

Review → Plan (safe, won't accidentally edit). Code changes → Agent (with approval gates). Batch simple edits → YOLO (fast, no approvals). Cycle with Tab.

3.2 Replace placeholder content

DeepSeek TUI
Replace all instances of "John Doe" with my real name. Update the skill descriptions, project descriptions, and about-me text with more natural placeholder content — no "Lorem ipsum".

Step 4: Add Advanced Features

4.1 Add dark/light theme toggle

DeepSeek TUI
Add a dark/light theme toggle to the site:
- Place a toggle button (☀️/🌙) on the right side of the navbar
- Clicking toggles data-theme attribute (dark ↔ light)
- Define two sets of CSS custom properties
- Persist user choice with localStorage
- Modify js/main.js and css/style.css

4.2 Add smooth scrolling and animations

DeepSeek TUI
Enhance the UX:
- Smooth-scroll to sections when clicking nav links
- Fade-in skill cards and project cards when they scroll into view
- Use IntersectionObserver (no third-party libraries)
⚡ Speed Up with YOLO Mode

When modifying a file you fully understand and the change direction is clear, press Tab to switch to YOLO mode. This skips approval steps and speeds things up. Switch back to Agent mode afterward.

Step 5: Review & Deploy

5.1 Final review

Switch back to Plan mode for a final check:

DeepSeek TUI (Plan mode)
Do a final review of the entire project. Check:
- All links are valid
- Mobile layout at 375px width
- Alt text on all images
- Page load performance (render-blocking resources)
List all issues found.

5.2 Initialize Git and commit

Terminal
$ git init
$ git add .
$ git commit -m "Initial portfolio website"

5.3 Deploy to GitHub Pages (free)

  1. Create a new repo my-portfolio on GitHub
  2. Push your code:
Terminal
$ git remote add origin git@github.com:your-username/my-portfolio.git
$ git branch -M main
$ git push -u origin main
  1. In the GitHub repo → Settings → Pages → Source, select the main branch
  2. After a few minutes, visit https://your-username.github.io/my-portfolio
✅ Congratulations!

You've built and deployed a complete portfolio website using DeepSeek TUI. Throughout this process, you wrote requirements — not code. That's the core workflow of AI-assisted development.

Tip Summary

Five Elements of an Effective Prompt

ElementExample
1. Deliverables"Create three files: index.html, style.css, main.js"
2. Section-by-section"Navbar includes... Hero includes... Skills include..."
3. Design constraints"Dark theme, responsive, CSS custom properties only"
4. Tech limits"No third-party libs, use IntersectionObserver"
5. Plan first"List the file structure first, wait for confirmation before coding"

The Typical Iteration Loop

  1. Describe requirements → Agent generates code
  2. Preview result → Open in browser
  3. Give feedback → "The navbar is too dark, make it semi-transparent"
  4. Review code → Switch to Plan mode and inspect
  5. Repeat 1-4 until satisfied

Mode Selection Quick Reference

What You're DoingMode to Use
Exploring, reviewing codePlan (read-only, safe)
Writing code, editing files, daily devAgent (default, with approval)
Batch replacements, trusted repetitive opsYOLO (fast, no approval)
