Core Concepts

Understand the foundational ideas that make DeepSeek TUI an effective AI collaborator.

Agent Modes

DeepSeek TUI operates in distinct modes that control how autonomously it works. Choosing the right mode for your task is one of the most important decisions you'll make.

Plan Mode

Plan mode is read-only investigation. The agent can grep, read files, list dirs, fetch URLs — but never writes files or shells out. Safe for exploration.

  • Best for: codebase exploration, reading docs, unfamiliar projects
  • Behavior: purely read-only, zero side effects, no file modifications
  • Safety: highest — no write or execute capability

Agent Mode (Default)

The default multi-step tool-use mode. Shell and side-effectful tools require approval per approval_mode setting.

  • Best for: day-to-day development, code changes, running tests
  • Behavior: creates plans and checklists, asks for approval at key operations
  • Safety: medium — gated by approval policy

YOLO Mode

YOLO mode grants full autonomy — auto-approves everything and enables trust mode, lifting the workspace boundary. Use carefully.

  • Best for: well-defined tasks, trusted workflows, rapid iteration
  • Behavior: moves fast, executes immediately, still creates checklists for visibility
  • Safety: lower — trust the agent or review changes after the fact
🔄 Mode Switching

Press Tab to cycle modes (Plan → Agent → YOLO), Shift+Tab to cycle reasoning effort. Start in Plan mode for unfamiliar code, use Agent mode for daily work, switch to YOLO for clear-cut tasks.

Auto Mode (Smart Routing)

With --model auto, DeepSeek TUI automatically selects the best model and reasoning level for each turn — no manual switching required.

How Auto Mode Works

  1. Before the real request, a lightweight deepseek-v4-flash routing call (thinking off) is made
  2. The router inspects your request and context, then selects a concrete model and thinking level
  3. Simple questions → Flash + thinking off; coding/debugging/architecture → Pro + high thinking
Shell
# Launch with Auto mode
$ deepseek --model auto

# Or switch during a session
/model auto
🎯 Recommended for Beginners

Not sure which model to pick? Use --model auto. The system decides for you, balancing cost and quality. The TUI header shows which model actually ran.

Thinking Budget

DeepSeek V4 models emit thinking tokens — internal reasoning that improves output quality but consumes context. DeepSeek TUI lets you control this trade-off.

Budget Levels

Task TypeDepthExamples
Simple lookupSkipReading a file, searching for a pattern
Tool output interpretationLightVerifying a grep result
Code generationMediumWriting a single function
Multi-file refactorMediumCross-file dependency changes
DebuggingDeepRoot-cause analysis
Architecture designDeepTrade-offs, constraint modeling
Security reviewDeepAdversarial reasoning

Think once, reference many times. Cache conclusions in concise inline summaries rather than re-deriving each turn. This keeps thinking efficient across long sessions.

Decomposition Philosophy

DeepSeek TUI is a "managed genius" — it excels at individual tasks, but its superpower is decomposing complex work. Three patterns govern this:

PREVIEW — Survey Before Diving

Before tackling a large task, scan directory structure, file headers, and module trees. A 30-second preview prevents hours of wrong-path exploration.

CHUNK + Map-Reduce

Split independent sub-tasks, process each in parallel (via sub-agents or parallel tool calls), then synthesize findings into a coherent whole.

RECURSIVE Decomposition

When sub-tasks reveal sub-problems: decompose recursively until each leaf is tractable. Maintain the task tree and propagate findings upward.

Context Window & Cache

DeepSeek TUI has a 1M-token context window with an intelligent prefix-cache system. Understanding how this works helps you get the most out of long sessions.

Prefix Cache Economics

  • V4 caches shared prefixes at 128-token granularity
  • Cache hits get ~90% cost discount
  • Appending to existing messages preserves the cache
  • Deleting or mutating old messages breaks the cache

Cache Management

  • Append, don't reorder — new context goes at the end
  • Don't paraphrase quoted content — refer by path or line range
  • Use /compact as a hard reset, not a tweak
  • Read once, refer back — re-reading breaks the cache

Session Management

DeepSeek TUI supports save, resume, and fork for sessions. Pick up right where you left off — even after closing your terminal or rebooting.

Key Operations

  • Auto-save: Every conversation is saved automatically — no manual steps needed
  • Resume: deepseek resume --last restores your most recent session
  • Fork: deepseek fork <SESSION_ID> creates a branch at a chosen turn
  • List: deepseek sessions shows all saved sessions
  • Rollback: /restore or revert_turn reverts to previous state (doesn't touch your git repo)
💾 Workspace Isolation

Sessions are saved and listed per workspace. Project A's history won't leak into Project B. Each project maintains its own independent session list.

Tool System

DeepSeek TUI provides a structured toolbox for interacting with your project. All tools operate within the workspace boundary for safety.

Tool Categories

📁
File I/O
read_file, write_file, edit_file, apply_patch — safe, workspace-constrained file operations.
💻
Shell
exec_shell, task_shell_start — run commands, tests, builds, and long-running processes.
🔍
Search
grep_files, file_search, web_search — find code patterns, files, and web resources.
📋
Planning
update_plan, checklist_write — structured task tracking with visible progress.

Parallel-First Heuristic

Before firing any tool, scan your checklist: is there another tool you could run concurrently? The dispatcher runs parallel tool calls simultaneously — serializing independent operations wastes time and context.
