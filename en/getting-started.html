Getting Started

Install, configure, and launch your first DeepSeek TUI session in minutes.

What is DeepSeek TUI?

DeepSeek TUI is a terminal-based AI coding assistant powered by DeepSeek V4 models. It runs directly in your terminal, giving you an agentic pair programmer that can:

  • Read and write files in your project workspace
  • Execute shell commands for testing, building, and diagnostics
  • Search and navigate your codebase with structured tools
  • Decompose complex tasks into plans, checklists, and sub-agent workflows
  • Operate autonomously in YOLO mode or collaboratively in Plan mode
🖥️ TUI = Terminal User Interface

Unlike web-based AI tools, DeepSeek TUI runs entirely in your terminal. This means it has direct filesystem access, shell integration, and fits naturally into your existing Unix workflow.

Installation

Linux & macOS

Via Cargo

Shell 
$ cargo install deepseek-tui-cli --locked
$ deepseek

Via npm

Shell 
$ npm i -g deepseek-tui
# First run sets up ~/.deepseek/

Requires Rust 1.88+ or Node >=18.

Via Homebrew (macOS)

Shell 
$ brew tap Hmbown/deepseek-tui
$ brew install deepseek-tui

Direct Download (no package manager)

Download prebuilt binaries from GitHub Releases. Available for Linux x64/ARM64, macOS x64/ARM64, Windows x64.

Via Docker

Shell 
$ docker run --rm -it \
    -e DEEPSEEK_API_KEY \
    -v "$PWD:/workspace" \
    ghcr.io/hmbown/deepseek-tui:latest

Windows

WSL2 (Recommended)

DeepSeek TUI runs natively under WSL2. Follow the Linux installation steps inside your WSL terminal.

Scoop Package Manager

PowerShell 
$ scoop update
$ scoop install deepseek-tui
$ deepseek --version
🇨🇳 Users in China

Speed up npm with --registry=https://registry.npmmirror.com. Cargo users can configure a Tsinghua mirror.

Verify Installation

Shell 
$ deepseek --version
deepseek-tui 0.8.31

API Key Setup

On first launch you'll be prompted for your DeepSeek API key (get one here). You can also set it ahead of time:

Shell
# Save to config file (recommended, works from any directory)
$ deepseek auth set --provider deepseek

# Check current auth status
$ deepseek auth status

# Or use an environment variable (for non-interactive shells)
$ export DEEPSEEK_API_KEY="sk-your-key-here"

# Verify everything works
$ deepseek doctor
💡 Auth Priority

Saved config keys take precedence over environment variables and the system keyring, and are easier to rotate. Use deepseek auth clear --provider deepseek to remove a saved key. If deepseek doctor reports a rejected key, check for stale environment variable exports.

Configuration

DeepSeek TUI stores its configuration in two key locations:

Config files 
~/.deepseek/           # Main config directory
├── config.toml        # Core configuration
├── instructions.md    # Custom project instructions (auto-generated)
├── skills/            # Installed skills
├── memories/          # Persistent memory store
└── plugins/           # Plugin system

Essential Settings

Edit ~/.deepseek/config.toml:

config.toml
[api]
key = "sk-..."
base_url = "https://api.deepseek.com"
model = "deepseek-v4-pro"  # default; deepseek-v4-flash is the fast / sub-agent option

[ui]
default_mode = "agent"     # plan | agent | yolo
approval_mode = "suggest"  # suggest | auto | never
reasoning_effort = "high"  # off | high | max

Project Instructions

The instructions.md file in your project root is auto-generated and tells DeepSeek TUI about your project structure, language preferences, and workspace boundaries. You can edit it to add project-specific guidance.

Your First Session

  1. Navigate to your project
    Shell
    $ cd ~/my-project
  2. Launch DeepSeek TUI
    Shell
    $ deepseek
  3. Write your first prompt

    The interface opens in your terminal. Try a simple task to get comfortable:

    DeepSeek TUI
    Summarize the project structure and key files.
✅ Successful First Session

The agent will read your project files, respond with analysis, and wait for your next instruction. You're now pair-programming with AI.

More Ways to Launch

Shell
# Interactive TUI (default)
$ deepseek

# One-shot prompt (non-interactive)
$ deepseek "Explain what this function does"

# Specify a model
$ deepseek --model deepseek-v4-flash "Summarize the README"

# Auto-select model and thinking level (recommended for beginners)
$ deepseek --model auto "Fix this bug"

# Full auto mode (auto-approves all actions — use carefully)
$ deepseek --yolo

# List available models
$ deepseek models

# List saved sessions
$ deepseek sessions

# Resume the last session
$ deepseek resume --last

Workspace Model

DeepSeek TUI operates within a workspace — the directory where you launched it. All file operations are relative to this root. This is a security boundary: tools cannot read or write files outside the workspace without explicit trust mode.

Key Concepts

  • Working directory: The directory passed to deepseek or set via cd
  • Workspace root: The top-level project directory
  • Active paths: Files the agent is currently focused on
  • Trust mode: Grants access outside the workspace when needed
⚠️ Security Note

By default, DeepSeek TUI constrains file access to the workspace. Enable trust mode only when you need cross-project operations and review tool calls carefully.

Sandbox Protection

DeepSeek TUI uses OS-level sandboxing to constrain tool execution:

  • Linux: landlock
  • macOS: seatbelt
  • Windows: AppContainer / restricted tokens

Troubleshooting

API Key Rejected

Symptom: deepseek doctor reports an invalid or rejected key.

  • Run deepseek auth status to see the active credential source
  • Check for a stale DEEPSEEK_API_KEY environment variable overriding your config
  • Run deepseek auth set --provider deepseek to re-save
  • Confirm your key is from the DeepSeek Platform and hasn't expired

Command Not Found

Symptom: Terminal says deepseek: command not found.

  • Cargo install: ensure ~/.cargo/bin is in your $PATH
  • npm install: ensure the npm global bin directory is in $PATH (check with npm bin -g)
  • Re-open your terminal or run source ~/.bashrc

Agent Output Not Matching Expectations

Symptom: The agent generates code that doesn't match your requirements.

  • Prompt too vague: See Prompt Engineering for improvement tips
  • Context too long: Run /compact then retry
  • Wrong mode: Plan mode is read-only — confirm you're in Agent or YOLO mode

How to Undo Mistakes

  • Undo the last turn: Type /restore in the conversation to roll back files
  • Undo a specific turn: Use the revert_turn tool
  • Git safety: Operations never touch your .git directory — use git diff anytime to review changes
🩺 Diagnostic Command

When in doubt, run deepseek doctor — it checks config, connectivity, and common misconfigurations, and suggests fixes.
