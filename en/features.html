Features Guide

Deep dive into the advanced capabilities that make DeepSeek TUI a powerful development platform.

Sub-Agents

Sub-agents are the key to parallel work in DeepSeek TUI. You can spawn multiple sub-agents that run concurrently, each focused on a single task, then synthesize their findings.

Why Use Sub-Agents?

  • Speed: Parallel investigation is faster than sequential reading
  • Thoroughness: Each sub-agent focuses deeply on one thing
  • Cost: DeepSeek V4 Flash costs $0.14/M input — sub-agents are cheap

Sub-Agent Types

TypeRoleWhen to Use
exploreInvestigationUnderstanding unfamiliar code, surveying module trees
planStrategyDesigning architectures, creating implementation plans
implementerExecutionWriting code, applying patches, building features
reviewVerificationCode review, security audit, quality gates
verifierTestingRunning tests, validating behavior

Pattern: Parallel Investigation

Conceptual
# Spawn sub-agents in parallel for independent files
agent_spawn("Analyze auth module", type="explore")    # Runs concurrently
agent_spawn("Analyze API routes", type="explore")      # Runs concurrently
agent_spawn("Analyze database layer", type="explore")  # Runs concurrently

# Wait for all to finish, then synthesize
agent_wait(wait_mode="all")

Concurrency Cap

Default maximum: 10 concurrent sub-agents (configurable via [subagents].max_concurrent). For larger batches, spawn up to the cap, wait, then spawn the next batch.

RLM — Recursive Language Model

RLM is for inputs that don't fit in your context window — whole files >50K tokens, long transcripts, multi-document corpora. It loads the input into a Python REPL where you process it with child LLM calls.

RLM Patterns

  • CHUNK: Split a large input, process each chunk, synthesize
  • BATCH: Classify/extract from many independent items in parallel
  • RECURSE: Decompose + critique for complex analysis
💡 When to use RLM

Use RLM for genuinely large inputs. For exact counts or structured aggregates, compute them directly in Python inside the REPL and report the deterministic result.

Task Management

DeepSeek TUI provides a durable task system for long-running, restart-aware work. Tasks persist across sessions and track progress with structured evidence.

Task Primitives

  • task_create: Enqueue a durable background task
  • task_list / task_read: Monitor progress and history
  • task_cancel: Cancel queued or running tasks
  • task_gate_run: Run verification gates (fmt, clippy, test)

Task Evidence

Tasks record structured evidence: gate results, PR attempts, verification notes, and file changes. This creates an audit trail for complex multi-step work.

Skills System

Skills are local instruction sets stored in SKILL.md files. They extend DeepSeek TUI's capabilities with domain-specific knowledge — from Android clean architecture to content marketing.

Skill Lifecycle

  1. Install: Skills live in ~/.deepseek/skills/
  2. Discover: Available skills are listed in the session header
  3. Load: Call load_skill("skill-name") to pull the SKILL.md body into context
🎯 Skill Creator

Use the built-in Skill Creator skill to create your own domain-specific skills. It guides you through frontmatter, structure, and best practices.

Create Your Own Skill

A skill is a directory with a SKILL.md file. Here's a simple example:

SKILL.md
---
name: my-python-style
description: Use when writing or reviewing Python code.
---

# Python Style Guide

- Use type hints on all functions
- Prefer dataclasses over plain classes
- Use ruff for formatting and linting
- Max line width 100 characters

Commands: /skills (list), /skill <name> (activate), /skill new (scaffold), /skill install github:<owner>/<repo> (community install).

MCP Servers

DeepSeek TUI supports the Model Context Protocol (MCP), allowing you to connect external tool servers to extend its capabilities.

Configuration Example

Configure in ~/.deepseek/mcp.json:

mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me"]
    },
    "sqlite": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path", "./data.db"]
    }
  }
}

Once configured, MCP server tools auto-register as mcp_<server>_<tool>. Use deepseek mcp list to view configured servers and deepseek mcp validate to check connectivity.

GitHub Integration

DeepSeek TUI integrates with GitHub for issue tracking, PR review, and structured acceptance workflows.

Available Operations

  • github_issue_context: Read issue body and comments
  • github_pr_context: Read PR with diffs and review state
  • github_comment: Post evidence-backed comments
  • github_close_issue: Close issues with acceptance evidence

All write operations require structured acceptance evidence — you can't close an issue without proving the work is done.

Memory System

DeepSeek TUI supports cross-session persistent memory. When enabled, the agent remembers your preferences and key decisions, automatically referencing them in future sessions.

How to Enable

Shell
# Enable via environment variable
$ export DEEPSEEK_MEMORY=on

# Or in config.toml
# [memory]
# enabled = true

Memory files are stored in ~/.deepseek/memories/, organized per project. The agent automatically uses the note tool to record important information during relevant tasks.

Checklists & Plans

DeepSeek TUI's planning system makes complex work visible and trackable. The sidebar shows Plan / Todos / Tasks / Agents so you always know what's happening.

Planning Tools

  • update_plan: High-level strategy (3-6 phases)
  • checklist_write: Granular leaf tasks under the current phase
  • checklist_update: Mark tasks in_progress or completed

Best Practice

Always create a checklist_write before starting work. Even with auto-approval, visible tracking demonstrates thoroughness and helps the user follow your progress.
