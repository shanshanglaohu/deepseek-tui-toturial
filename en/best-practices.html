Best Practices

Production-tested patterns that make DeepSeek TUI sessions productive, safe, and efficient.

Verification-First Development

The single most important practice: verify before proceeding. After every tool call that produces a result you'll act on, confirm the output matches expectations.

Verification Checklist

  • File reads: Confirm line numbers match what you're about to patch
  • Shell commands: Check stdout, not just exit code
  • Search results: Confirm the match is what you expected (false positives happen)
  • Sub-agent results: Cross-check one finding against a direct read
🚫 Don't trust memory

Never patch from memory. Live tool output is the only source of truth. Memory fails; tool output doesn't lie.

Prompt Engineering

DeepSeek TUI responds to structured, concrete instructions. Vague prompts produce vague results. Here's what works:

Effective Patterns

  • Name the action: "Reading the module tree" not "Let me take a look"
  • Specify the output: "Return a list of 3-5 bullet points" not "Tell me about..."
  • Constrain scope: "In src/auth/ only" not "Find all the bugs"
  • Give context: "After the refactor in PR #42..." not "Fix this code"

Vague vs. Specific: Real Examples

❌ Vague Prompt✅ Specific Prompt
"Make me a website""Create a single-page portfolio site with navbar, hero section, skill cards, project showcase, and contact form. Dark theme, responsive, pure HTML/CSS/JS."
"Fix this bug""The form submit button doesn't respond when clicked. Check js/form.js for the submit event handler — verify it correctly prevents default behavior."
"Optimize performance""Homepage loads in 3.2 seconds. Check which resources block rendering. Prioritize images >100KB and CSS files first."
"Refactor the code""Extract the 5 date utility functions from src/utils.js into a separate dates.js module. Keep the existing export interface unchanged. Update all imports."

Prompt Structure for Complex Tasks

  1. Goal: One-line objective
  2. Constraints: What's off-limits
  3. Context: Relevant files, PRs, decisions
  4. Expected output: What success looks like

Context Management

Your 1M-token window is generous but not infinite. Smart context management keeps sessions productive for hours.

The Cache-Aware Workflow

  • Batch reads: Read 3+ files in one turn instead of sequentially
  • Batch tool calls: grep + read + git_status in one turn
  • Append, don't rewrite: New findings go at the end
  • Reference by path: "In auth.rs:42" not "Here's the code again..."

When to /compact

Suggest compaction when context use creeps above 80%. Treat it as a hard reset, not a tweak. The system preserves working files and recent decisions.

⚠️ Cache decay

Monitor the cache hit % chip. Red (<40%) for several turns = consolidate. Yellow (<80%) = watch. Green = healthy.

Delegation Patterns

When to Delegate to Sub-Agents

Use sub-agents for independent, parallelizable work. Good candidates:

  • Investigating 3+ independent files or modules
  • Parallel implementation of independent leaf tasks from a plan
  • Running code review alongside your main work

Anti-Patterns

  • Don't delegate single-file reads: A direct read is faster
  • Don't pre-spawn dependent work: Wait for step A's output before spawning step B
  • Don't forget to synthesize: Sub-agent output needs integration

Cost Management

While DeepSeek TUI is inexpensive, long sessions and many sub-agents can add up. Here's how to keep costs under control:

Cost Optimization Strategies

  • Use Auto mode: Simple questions automatically use Flash (cheap), complex ones use Pro
  • Maximize cache hits: Append, don't reorder messages — cache hits >80% save ~90% on input costs
  • Match reasoning to task: File reads need no reasoning (off); coding benefits from high; architecture needs max
  • Batch operations: Read 3+ files at once instead of one at a time to reduce turn count
  • Limit sub-agent count: Each sub-agent is an independent API call — keep them necessary
  • Compact regularly: Compact long sessions at ~80% context to reduce subsequent token consumption
📊 Typical Cost Reference

A medium-complexity coding session (50 turns, with sub-agents) using Flash typically costs $0.05–$0.20. The same work with Pro costs about $0.50–$2.00. The TUI header shows total session cost in real time.

Common Pitfalls

Overthinking Simple Tasks

Match thinking depth to task complexity. A file read doesn't need deep reasoning. Save deep thinking for debugging and architecture.

Serializing Independent Work

If two operations don't depend on each other, batch them. The dispatcher runs parallel tool calls simultaneously. Serializing wastes time and context.

Empty Sidebars

The sidebar shows Plan / Todos / Tasks / Agents. When these panels are empty, users have no idea what you're doing. Keep them populated with checklist_write and update_plan.

Blindly Following Plans

Re-read your plan after each phase. Does phase 2 still make sense? Update if new information changes the approach. Don't follow a plan drafted before you understood the code.

Patch Without Reading

Always read_file before edit_file. Line numbers shift. Code changes between reads. Your memory of a file from 10 turns ago is unreliable.
